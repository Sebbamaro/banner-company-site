# Сайт производства и монтажа баннеров

Статические HTML + CSS/JS; PHP 8.2+, MySQL 8 / MariaDB 10.6+, Composer. Node в production не нужен. Исходные данные компании: `config/company.json`, портфолио: `config/portfolio.json`. Пересборка: `python3 bin/build.py` (Python 3 нужен только на машине сборки). Сгенерированные страницы коммитятся в Git.

## Локальный запуск

```sh
cp .env.example .env
python3 bin/build.py
docker compose up -d --build
docker compose run --rm app composer install --no-interaction
docker compose exec app php bin/migrate.php
# сайт: http://localhost:8080
```

Дождитесь healthy у БД (`docker compose ps`). Без Docker: PHP 8.2+ с PDO MySQL, mbstring, curl, openssl; Composer 2; MariaDB. `composer install`, заполнить `.env`, `php bin/migrate.php`, `php -S localhost:8080 -t public`.

По умолчанию APP_MODE=demo: сервер проверяет поля, **не сохраняет** и **не отправляет** уведомления; ответ явно тестовый. Для реального сохранения включить production, заполнить домен, оператора и компанию, APP_ORIGIN и RATE_SALT (случайные 32+ байта), настроить БД. При отсутствии БД — HTTP 503 без успеха. Для тестирования сохранения используйте интеграционные тесты с mock-адаптерами, не внешние отправки.

## Проверки

```sh
docker compose exec app php tests/run.php
docker compose exec app php tests/integration.php
docker compose exec app php tests/http.php
python3 tests/static.py
```

Интеграционный тест создаёт и удаляет отдельную базу `banner_test`, требуется root-доступ только к локальной тестовой БД. Никогда не запускать на production. `TEST_DB_DSN`, `TEST_DB_USER`, `TEST_DB_PASSWORD` задают отдельную тестовую БД; имя должно оканчиваться на `_test`.

## Что заполнить перед публикацией

- Название, город и точная территория работы (не подтверждены ссылкой Avito), телефон, email, Telegram, адрес, часы, реквизиты, домен в `config/company.json`.
- Уточнить перечень услуг: сейчас только изготовление/печать и монтаж баннеров. Демонтаж и вывески не заявлены. Новая услуга добавляется в массив services с уникальным slug — сборщик создаёт страницу и навигацию.
- Подтвердить условия, сроки и материалы; цены, отзывы, стаж и гарантии не выдуманы.
- Заполнить и проверить с ответственным специалистом тексты в `bin/build.py`: оператор, цели, основания, сроки, получатели и обработчики, порядок обращений и удаления, используемые сервисы, применимые организационные требования. Сейчас документы — проекты с placeholders; техническая реализация не гарантирует соответствие закону.
- Выбрать российское размещение БД и почты, срок RETENTION_DAYS (пример 90 дней не юридическая рекомендация), порядок резервного копирования и удаления копий. Согласовать передачу технических уведомлений Telegram.
- Настроить SMTP, Telegram, HTTPS, cron, резервные копии; проверить тестовую заявку с разрешения владельца. Реальные уведомления в этой задаче не отправлялись.
- Метрика выключена (metrikaId пуст). Включать после проверки оснований и настроек приватности. Статистика не получает значения полей; рекламные метки не должны содержать ПД. Не передавайте ПД в адресах страниц и UTM.

## Фотографии

Сейчас портфолио отсутствует во всех меню, на главной и в sitemap. Добавьте реальные фотографии в `public/assets/images/work/` и запись в `config/portfolio.json`:

```json
[{"published":true,"title":"Название работы","description":"Фактическое описание","images":[{"src":"/assets/images/work/banner.webp","alt":"Что изображено на фотографии","width":1200,"height":800}]}]
```

Перед добавлением удалите EXIF и персональные данные, получите права на публикацию. Экспортируйте WebP/AVIF подходящего размера (рекомендуется до 1600px, до 250 КБ). Галерея адаптивна, изображения загружаются лениво, размеры предотвращают скачки вёрстки. После `python3 bin/build.py` первая опубликованная работа автоматически включает раздел. Локальные тестовые изображения не коммитить. Иллюстрация первого экрана — графика, а не кейс компании.

## Очередь и хранение

Сначала транзакция заявки и двух заданий, затем cron. Запуск: `php bin/queue.php`; очистка: `php bin/purge.php`. Никакого кабинета нет. SQL — prepared statements, источник страницы ограничен путём, IP хранится только в краткоживущем HMAC-лимитере. Не доверяйте X-Forwarded-For без настройки доверенного прокси; лимитер использует REMOTE_ADDR. HTTPS обязателен.

Очередь блокирует строку задания и заявки, SKIP LOCKED позволяет несколько работников. У каналов независимые статусы и попытки, задержки 60/120/240/480 секунд, максимум 5 (настраивается). Telegram отправляется один раз после подтверждённого успеха, текст отражает состояние email на момент отправки; повторного сообщения об изменении email нет. Письмо не задаёт заголовки из пользовательских данных. Технические логи содержат только коды.

**Ограничение внешних API:** SMTP и Telegram не предоставляют общей транзакции с БД. Если сервис принял сообщение, но ответ потерян или процесс упал до commit, повторная попытка может дать дубликат. Абсолютное exactly-once не обещается. После записанного статуса sent повторов нет. Вызовы ограничены тайм-аутами. Не включайте отладочный SMTP-лог и логирование тел запросов.

Размещение, cron, SMTP, Telegram, SSH и восстановление: [docs/deployment.md](docs/deployment.md).

Браузерные проверки: `npm install --no-save --package-lock=false playwright` (или установленный Playwright), `CHROMIUM_PATH=/usr/bin/chromium node tests/browser.cjs`; требуется запущенный локальный сайт и APP_ORIGIN=http://localhost:8080. Тесты проверяют 360/768/1440px и демоформу. В этой облачной среде Composer установлен через `--prefer-source` с разрешённых официальных Git-репозиториев; на обычном хостинге подходит стандартный `composer install` из lockfile.
