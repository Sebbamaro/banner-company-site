# Проверка текущей реализации

Проверено локально в PHP 8.2-контейнере и MariaDB 11.4; реальные SMTP/Telegram-вызовы не выполнялись.

- `php tests/run.php`: 17 проверок нормализации, неверных данных, согласия, текстов Telegram, приватности и экранирования HTML письма.
- `php tests/integration.php`: 18 проверок на настоящей MariaDB с mock-адаптерами: сохранение, задания в транзакции, принудительный сбой outbox с rollback, независимые сбои каналов, backoff, исчерпание попыток, отсутствие повторов после sent, лимит частоты.
- `php tests/http.php`: 11 проверок через настоящий HTTP-обработчик в изолированном временном проекте: сохранение и HTTP 201, нормализация/валидация, honeypot, чужой Origin, недоступная БД → 503, отсутствие персональных данных в техническом логе.
- `node tests/browser.cjs`: 21 проверка в системном Chromium: 360/768/1440px, главная и остальные страницы без горизонтальной прокрутки, скрытое портфолио, валидация телефона, честный ответ демоформы и сохранение введённого комментария. Скриншоты просмотрены. Согласие исходно не отмечено.
- `python3 tests/static.py`: по одному H1, работающие внутренние ссылки, отсутствие фиктивного tel, включение портфолио с локальной временной картинкой и удаление её после проверки.
- Проверены PHP-синтаксис, JS-синтаксис, Python-компиляция, Composer manifest и повторный запуск миграции.

Не проверены на production: реальная доставка SMTP/Telegram, полномочия хостинга, DNS/HTTPS, cron и восстановление резервной копии. Их следует проверить после заполнения реквизитов и отдельного разрешения на внешние отправки. Автоматические браузерные проверки не заменяют ручной аудит доступности со скринридером. Внешние API имеют описанное в README окно неопределённого результата; абсолютного exactly-once нет.
